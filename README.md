# AirMic

AirMic is an iOS app that routes live audio from a chosen input device (e.g. a wired
microphone) to the current system output (e.g. a Bluetooth speaker) in real time, with
low latency. It exists because iOS does not natively let you pick an independent input
and output pair for audio pass-through — useful for presentations where a wired mic must
play through a Bluetooth speaker.

## Features

- **Input selection** — lists all available input ports (built-in mic, wired headset mic,
  Bluetooth mic) via `AVAudioSession.availableInputs`; pick one from a menu.
- **Output selection** — uses the system route picker (`AVRoutePickerView`, wrapped so it
  looks like the input dropdown) to choose a Bluetooth/AirPlay/wired output. iOS does not
  allow programmatic output selection, so this is the system UI.
- **Real-time routing** — `AVAudioEngine` graph (`inputNode → mainMixerNode → output`)
  with a short preferred IO buffer duration for low latency.
- **Gain control** — slider from 0% to 200%, applied via `mainMixerNode.outputVolume`.
- **Level meter** — horizontal bar driven by RMS level computed from a tap on the input
  node; green / yellow / red by loudness.
- **Background audio** — keeps routing when backgrounded or screen-locked
  (`UIBackgroundModes = [audio]`).
- **Route-change & interruption handling** — restarts the engine on device
  connect/disconnect; handles audio-session interruptions (e.g. phone calls).

## Requirements

- Xcode 14 or newer (project object version 56).
- iOS 16.0+ deployment target (iPhone and iPad).
- A physical device is required to exercise real audio routing. The Simulator has no real
  mic/Bluetooth audio routing and the route picker will not show external devices.
- Swift 5.0, SwiftUI.

## Build & Run

Open in Xcode:

```sh
open AirMic.xcodeproj
```

Select the **AirMic** scheme and a connected device, then Run (Cmd+R).

From the command line (the `AirMic` scheme is auto-generated by Xcode if not already
present — open the project in Xcode once if `xcodebuild` reports a missing scheme):

```sh
# Build for a connected device
xcodebuild -project AirMic.xcodeproj -scheme AirMic -configuration Debug build

# List available simulators / destinations
xcodebuild -project AirMic.xcodeproj -scheme AirMic -showdestinations
```

Code signing uses automatic signing with development team `3UP4MZRP69` and bundle
identifier `com.sudobility.airmic`. Change `DEVELOPMENT_TEAM` /
`PRODUCT_BUNDLE_IDENTIFIER` in the project's build settings to sign with your own account.

## Notes & Known Limitations

- **Audio session** is configured as `.playAndRecord` with mode `.measurement` (no AGC /
  noise suppression) and options `[.allowBluetooth, .allowBluetoothA2DP]`. Because
  `.measurement` mode ignores `.defaultToSpeaker`, the engine manually calls
  `overrideOutputAudioPort(.speaker)` when no external output is connected.
- **Output selection is system-controlled.** You cannot programmatically target a specific
  Bluetooth output; the invisible `AVRoutePickerView` surfaces the system picker.
- **"Forget Bluetooth device" deep link** (`App-prefs:Bluetooth`) is implemented in
  `AudioEngineManager.stop(openBluetoothSettings:)` but is **not** wired into the UI — the
  Start/Stop button calls `stop()` with the default `false`. `App-prefs:` is effectively
  private API and may be rejected in App Store review if enabled.
- **Feedback risk** — if input mic and output speaker are physically close, audio feedback
  can occur. Use the gain slider to manage it; there is no automatic feedback suppression.
- Pickers and input selection are disabled while the engine is running.
