# CLAUDE.md

## What this is

AirMic is an iOS app that routes live audio from a selected input device to the current
system output in real time (e.g. wired mic → Bluetooth speaker), working around iOS's
lack of independent input/output selection for audio pass-through. See `README.md` for
the full feature list and `plans/START.md` for the original design (now partly stale).

## Stack

- Swift 5.0, SwiftUI, `AVFoundation` / `AVAudioEngine`.
- iOS 16.0+ (iPhone + iPad). Xcode 14+ (pbxproj object version 56).
- Single Xcode target `AirMic`; no Swift Package / CocoaPods dependencies.

## Build / Run

- Open: `open AirMic.xcodeproj`, select scheme **AirMic**, Run on a device (Cmd+R).
- CLI build: `xcodebuild -project AirMic.xcodeproj -scheme AirMic -configuration Debug build`
- The `AirMic` scheme is Xcode-autogenerated and not committed; open the project in Xcode
  once if `xcodebuild` cannot find it.
- **No test target exists** — do not invent `xcodebuild test` instructions.
- Real audio routing requires a **physical device**; the Simulator lacks mic/Bluetooth
  routing and shows no external output devices in the route picker.

## Architecture

- `AirMicApp.swift` → `ContentView` (single screen).
- `Audio/AudioEngineManager.swift` (`@MainActor ObservableObject`): owns the `AVAudioEngine`
  and `AVAudioSession`. `start()` configures the session, overrides output, builds the
  `inputNode → mainMixerNode` graph, installs a metering tap, and starts the engine.
  Publishes `isRunning`, `audioLevel`, `gain`.
- `Audio/AudioDeviceManager.swift` (`@MainActor ObservableObject`): input discovery via
  `availableInputs`, `setPreferredInput`, current output name; observes route-change and
  interruption notifications. Publishes `availableInputs`, `selectedInput`,
  `currentOutputName`.
- `Views/`: `ContentView` composes `InputPickerView`, `OutputRouteButton`,
  `LevelMeterView`, a gain slider, and the Start/Stop button.

## Conventions

- Audio-state classes are `@MainActor final class ... : ObservableObject` with `@Published`
  state; UI reads them via `@StateObject` / `@ObservedObject`. Keep new audio state on the
  main actor; the metering computation is `nonisolated` and hops back via `Task { @MainActor }`.
- Info.plist is mostly Xcode-generated (`GENERATE_INFOPLIST_FILE = YES`). The checked-in
  `Info.plist` holds only `UIBackgroundModes`; usage strings like
  `NSMicrophoneUsageDescription` live in build settings as `INFOPLIST_KEY_*` in the pbxproj,
  not in the plist file.

## Gotchas (non-obvious)

- Session uses mode `.measurement` (no AGC), which **ignores** `.defaultToSpeaker`; the
  engine calls `overrideOutputAudioPort(.speaker)` manually when no external output exists.
  Don't "fix" this by adding `.defaultToSpeaker`.
- Route changes with reason `.override` are deliberately ignored in the route-change
  handler — they are triggered by our own `overrideOutputAudioPort` calls (avoids a restart
  loop).
- Output device selection is system-only via the (nearly invisible) `AVRoutePickerView` in
  `OutputRouteButton`; there is no programmatic output-selection API.
- `AudioDeviceManager.refreshDevices()` preserves previous device state when
  `availableInputs` is empty (session inactive after stop) instead of clearing it.
- The `App-prefs:Bluetooth` deep link in `stop(openBluetoothSettings:)` is implemented but
  unused (UI calls `stop()` with default `false`); it is private API and App-Store-risky.
